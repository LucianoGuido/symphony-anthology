Why Anthology exists

Utility-heavy HTML is fast to assemble but harder to read, maintain, and understand for both humans and generators. Anthology starts from semantic structure instead.

The goal is a semantic default that stays legible for authors, generators, and audits: stable semantics, predictable variants, and machine-readable metadata for generators, audits, and search systems.

Three levels, one mental model

  1. Semantic HTML by default. Start with headings, paragraphs, lists, forms, tables, articles, and navigation.
  2. Data attributes for intent. Use `data-variant`, `data-size`, `data-layout`, and similar attributes only when needed.
  3. Optional primitives. Container, grid, stack, cluster, and related helpers stay available for more complex compositions.

Example

A product section can be represented with an article, a heading, supporting text, a price, and a primary action. That structure is readable without framework-specific knowledge.
